# Ask OLake

> **Your source-backed technical guide to OLake.**

Ask OLake is a fast, citation-first AI assistant built to answer technical questions about **OLake** using official documentation and approved open-source repositories. Every answer is grounded directly in indexed official sources and accompanied by clickable citation markers and verified source URLs.

---

## Key Capabilities

- **Installation & Setup**: Docker Compose quickstarts, configuration profiles, environment variables, and ports.
- **Connectors & CDC**: PostgreSQL (including `pgoutput` vs. deprecated `wal2json`), MySQL, MongoDB (change streams), Oracle, DB2, MSSQL, Apache Kafka, and Amazon S3.
- **Sync Modes**: Full Refresh, Full Refresh + CDC, CDC Only, and Incremental Sync per connector.
- **Destinations & Catalogs**: Apache Iceberg and Parquet writers with REST, AWS Glue, Hive, and JDBC catalog integrations.
- **OLake Fusion & Compaction**: Automated Iceberg table maintenance, file layout self-optimization, and compaction types (**Lite**, **Medium**, and **Full**) with strict precedence (`Full > Medium > Lite`).
- **Deployments**: Official Helm charts for Kubernetes, worker configurations, Temporal orchestration, and Docker Compose environments.
- **Troubleshooting & Abstention**: Clear explanations of known error scenarios, and explicit abstention when features or configurations cannot be verified in official documentation.

## Architectural Pipeline

```
User Question
      │
      ▼
Input Validation (length <= 1500 chars, non-empty, type check)
      │
      ▼
Local Lexical Retrieval (BM25 + Technical Tokenizer + Metadata Boosting)
      │
      ▼
Evidence Selection (4-6 relevant chunks, deduplicated by URL & section)
      │
      ├── [Insufficient Evidence or Unknown Domain] ──► Immediate Abstention Response (sources: [])
      │
      ▼
OpenRouter Integration (Approved Models Only with Sequential Fallback)
  1. z-ai/glm-4.7-flash (Primary)
  2. google/gemini-2.5-flash-lite (Fallback 1)
  3. deepseek/deepseek-v4.1-flash (Fallback 2)
      │
      ▼
Citation Validator & Renumbering Engine
  - Rejects hallucinated source IDs (e.g. S99)
  - Maps evidence IDs to verified corpus URLs
  - Renumbers inline markers to match sources array: [1], [2]
      │
      ▼
Strict JSON Response Contract {"answer": "...", "sources": ["..."]}
      │
      ▼
Interactive Web Interface & Embeddable /embed Route
```

### Anti-Hallucination & Grounding Policy

1. **Evidence-Bound Answers**: The assistant treats retrieved official OLake files as the sole source of truth. It does not use LLM training memory to invent configuration flags, environment variables, or CLI commands.
2. **Explicit Abstention**: When evidence is missing or insufficient, Ask OLake abstains with a helpful message:
   > *"I couldn't verify that from the currently indexed OLake sources. I don't want to guess at a configuration or command. Try asking about the specific connector, deployment method, error message, or feature."*
3. **Structured Citation Enforcement**: The backend controls the returned `sources` list. The language model only references assigned IDs (`[S1]`, `[S2]`). Any fabricated ID or URL generated by the model is stripped before reaching the client.

## API Contract

### `POST /ask`

Submits a technical question to the assistant.

#### Request

```http
POST /ask HTTP/1.1
Content-Type: application/json

{
  "question": "Which sync modes are documented for PostgreSQL in OLake?"
}
```

#### Successful Response (`200 OK`)

```json
{
  "answer": "OLake supports Full Refresh, Full Refresh + CDC, CDC Only, and Full Refresh + Incremental for PostgreSQL [1]. The native pgoutput plugin is recommended as wal2json has been deprecated [2].",
  "sources": [
    "https://olake.io/docs/connectors/postgres",
    "https://olake.io/docs/connectors/postgres/wal2json_plugin"
  ]
}
```

#### Abstention Response (`200 OK`)

```json
{
  "answer": "I couldn't verify that from the currently indexed OLake sources. I don't want to guess at a configuration or command. Try asking about the specific connector, deployment method, error message, or feature.",
  "sources": []
}
```

#### Error Response (`400 Bad Request`)

```json
{
  "error": "Field \"question\" must be a string."
}
```

### `GET /version`

Returns runtime deployment and Git commit metadata directly from Vercel system environment variables (`VERCEL_GIT_COMMIT_SHA` and `VERCEL_DEPLOYMENT_ID`).

#### Response (`200 OK`)

```json
{
  "commit": "d06007140994ecbd239a52a9c0acf81fab4ed530",
  "deployment": "dpl_8Hq9Kj3MnP"
}
```

*Note: In local development, if environment variables are not set, it returns empty strings `""` rather than inventing metadata.*

---

### `GET /models`

Queries OpenRouter's user models endpoint (`https://openrouter.ai/api/v1/models/user`) at request time using the server-side API key and returns available model IDs without exposing credentials.

#### Response (`200 OK`)

```json
{
  "models": [
    "deepseek/deepseek-v4.1-flash",
    "z-ai/glm-4.7-flash",
    "google/gemini-2.5-flash-lite"
  ]
}
```

---

## Local Development & Setup

### Prerequisites

- **Node.js** v18+ (tested on Node v24.14.1)
- **npm** v9+ (tested on npm 11.11.0)
- **Git**

### 1. Installation

```bash
npm install
```

### 2. Environment Configuration

Copy the example environment file:

```bash
cp .env.example .env
```

Edit `.env` and configure your OpenRouter key:

```env
OPENROUTER_API_KEY=sk-or-v1-your-actual-key-here
PORT=3000
NODE_ENV=development
```

> **Security Note:** `.env` is listed in `.gitignore` and is never committed.

### 3. Running the Automated Tests

The automated test suite runs via Node's native test runner without consuming OpenRouter API credits:

```bash
npm test
```

The test suite executes 33 automated tests across 5 suites:
- **Organizer Benchmark Suite (20 Cases)**: Verifies all 8 sources, Iceberg/Parquet, 4 sync modes, cursor/deletes, bounded CDC, PG/MySQL/Mongo CDC prerequisites, metadata columns, upsert/append, Iceberg catalogs, UI install/creds, CLI flags, custom cron, and strict abstention/refusal on Cassandra, Delta Lake, 99.999% SLA, prompt injection, and secret disclosure.
- **API Endpoints (`/health`, `/version`, `/models`, `/ask`, `/embed`, `/demo`)**: Status codes, contracts, CORS preflight, timeouts, and error handling.
- **Provider & Model Rules**: Enforces strict prioritization of the 3 approved models (`z-ai/glm-4.7-flash`, `google/gemini-2.5-flash-lite`, `deepseek/deepseek-v4.1-flash`) with automatic fallback.
- **Retrieval Engine**: BM25 scoring, inverted index caching, and technical tokenization.
- **Citation Validator**: Citation mapping, deduplication, and hallucinated source stripping.

### 4. Typecheck & Production Build

```bash
npx tsc --noEmit
npm run build
```

### 5. Running Locally

```bash
npm start
```

## Deployment Guide (GitHub Integration with Vercel)

The official submission requires deployment through GitHub integration with Vercel:

1. **Commit & Push to GitHub**:
   ```bash
   git add .
   git commit -m "feat: complete Ask OLake Vercel deployment readiness"
   git branch -M main
   git remote add origin https://github.com/Afnan-0206/ask-olake.git
   git push -u origin main
   ```

2. **Import into Vercel**:
   - Go to [Vercel Dashboard](https://vercel.com/new).
   - Select **Import Git Repository** and select `Afnan-0206/ask-olake`.
   - Vercel automatically detects the Vite framework and settings from `vercel.json`.

3. **Configure Environment Variables**:
   - In **Project Settings** > **Environment Variables**, add:
     - `OPENROUTER_API_KEY`: *(your server-side OpenRouter API key)*
   - In **Project Settings** > **General** > **System Environment Variables**, ensure **Automatically expose System Environment Variables** is enabled (provides `VERCEL_GIT_COMMIT_SHA` and `VERCEL_DEPLOYMENT_ID`).

4. **Deploy & Verify**:
   - Click **Deploy**.
   - Wait for the build to reach the **Ready** state.
   - Verify all endpoints:
     - `curl -s https://<your-vercel-domain>/version`
     - `curl -s https://<your-vercel-domain>/models`
     - `curl -s https://<your-vercel-domain>/health`
     - `curl -X POST https://<your-vercel-domain>/ask -H "Content-Type: application/json" -d '{"question":"What is OLake?"}'`
     - Open `https://<your-vercel-domain>/demo` in an incognito window.

## Known Limitations

- **Corpus Freshness**: Knowledge is indexed from the 5 official repositories as of October 2026 (commit SHAs documented above). New commits to upstream repositories can be refreshed anytime using `npm run ingest`.
- **Model Token Bounds**: Max output tokens are bounded to 500 tokens to ensure low latency and concise, high-density documentation answers.
- **Abstention Discipline**: If a connector or feature has no supporting documentation in the official sources, the system explicitly abstains rather than generating speculative configuration values.
